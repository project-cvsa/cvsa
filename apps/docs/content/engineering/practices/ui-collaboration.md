`apps/web` 与 `apps/docs` 的图形界面由人类评审者直接把关视觉与交互质量，而不是依赖 Agent 截图自审。Coding Agent 负责组件结构、状态与 API 接线、单元与契约测试以及静态校验，人类评审者负责视觉层次、间距排版与实际操作手感。

## 为什么界面质量需要人类把关

当前的 Coding Agent 可以验证 TypeScript 编译、UnoCSS token 解析以及组件基本渲染，但缺乏稳定的视觉与审美判断力。如果由 Agent 通过无头浏览器截图自行放行界面改动，往往会引入多余的视觉噪音，例如冗余的包装卡片、装饰性角标、拥挤的多列布局或遮挡核心控件的说明文字。

将代码静态验证与视觉体验评审明确分开，可以让自动化工具专注于逻辑与契约正确性，同时让人类评审在真实界面中快速确认可用性。

## 职责分工

- **Coding Agent 负责结构、逻辑与静态验证**：使用 `@lib/cn` 的 `cn()`、`cva()` 与语义化设计 token（`ts-*`、`bg-surface`、`text-primary`、`border-border`、`bg-scrim`）构建组件，通过 `@api-contract` 与 `@lib/api` 接线后端契约，编写逻辑与 token 测试，并执行 `bun run ci`、`bun run typecheck` 与 `bun run --cwd apps/web test`。除非用户明确要求，否则 Agent 不启动本地开发服务器或打开浏览器自审界面。
- **人类评审者负责视觉与交互验收**：在本地运行应用，跨视口尺寸操作控件，确认对齐、间距、空白态与周边页面的整体一致性。

修改既有界面时，应优先沿用现有的组件尺寸、排版 token 与导航结构，不擅自引入新的顶层入口或复杂装饰。

## 让深层界面状态易于检验

许多关键界面状态（多步弹窗、空白列表、加载过渡、错误横幅或依赖特定后端记录的详情视图）在真实联调时难以一步到达。保持状态流转显式清晰，并在单元测试或独立预览中使用接近真实数据的测试样本驱动，便于评审者直接查看空状态、加载态、常规态与错误态的完整表现。
