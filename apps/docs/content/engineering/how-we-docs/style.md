清晰一致的写作与排版让开源贡献者和 Coding Agent 都能快速定位事实，减少歧义与无效上下文。

## 语气与开篇原则

按照文档类型确定开篇句式与人称，跳过「本文档介绍了……」「本规约定义了……」一类元叙事废话，也不要在未指明主语前用「该仓库」「这些组件」开头。

- **操作类文档（`how-to` 与 `tutorial`）**：开篇直接说明读者将完成什么任务以及需要满足的前置条件；步骤中使用祈使句，把条件放在动作之前（例如「如未启用本地数据库，请先执行……」）。
- **概念与参考类文档（`reference`、`explanation`、`plan`）**：直接以系统、契约或设计问题作为开篇主语，说明它规范或解释的对象。
- **对比句克制使用**：只有当对比能揭示真实的技术权衡、错误边界或常见误区时才使用「而不是」「而非」；若删掉对比从句后规则依然完整清晰，则直接写出正向规则。

## 禁用空洞套话与伪严谨行话

以直白、字面准确的工程语言描述系统实际计算、校验或输出的行为，不使用商业宣传词（如「无缝」「全面赋能」「生产级」）、组织黑话或伪严谨套话。写作中避免出现以下词汇与句式：

- **禁止伪严谨术语**：不使用官僚腔、空洞口号或过度修饰的行政术语（例如统一使用「查看」「确认」「运行验证」「筛选」「搜索」「查询」「记录操作人」「撤销」「散列摘要」「测试数据」等直白表达，具体禁用词清单见根目录 [`AGENTS.md`](https://github.com/project-cvsa/cvsa/blob/main/AGENTS.md)）。
- **禁用空洞免责套话**：避免「不是……」「不代表……」「不能声称……」等法律化声明，直接说明系统当前已实现的能力与已知限制。

## 双语混排与术语一致

工程知识库以中文为主（部分特定协作成文保留英文），遵循以下双语混排与术语约定：

- **中英文空格**：中文字符与英文单词、数字或行内代码之间保留一个半角空格，例如「运行 `bun run test` 完成测试」；全角中文标点（`，`、`。`、`：`、`、`）紧贴文字，不额外加空格。
- **核心领域术语**：代码标识符与数据库字段使用反引号保留英文原名，中文叙事保持固定译名对照：

| 英文/代码概念 | 中文常用译名 | 说明 |
| :--- | :--- | :--- |
| `Song` | 曲目 / 歌曲 | 核心编目实体，对应 `core.song`。 |
| `Artist` / `ArtistRole` | 创作者 / 创作角色 | P 主、词曲、调校等创作者与角色定义。 |
| `Singer` / `Voicebank` / `SvsEngine` | 歌手 / 声库 / 合成引擎 | 虚拟歌手与歌声合成引擎及版本。 |
| `VideoTracking` / `VideoSnapshot` | 视频追踪 / 视频快照 | 时序数据采集状态与某时刻播放数据采样。 |
| `VideoAnnotation` / `VideoCuration` | 候选标注 / 策展裁决 | 发现样本的人工打标记录与最终收录裁决。 |

## 标点与句子结构

- **少用破折号与分号链**：当两个从句之间存在因果、转折或并列关系时，拆成短句或使用「因为」「同时」「因此」明确逻辑关系，不要用一长串破折号或逗号把多个不相关动作揉进同一句。
- **密集枚举转为列表或表格**：超过三项的目录列表、配置项或参数说明，从长段落拆出为无序列表或 Markdown 表格，每张表格控制在四列以内，单元格不超过一句话。
- **克制使用粗体引导词**：仅在定义明确术语、配置键或文档类型时使用粗体前缀（例如 `**`draft`**：`）；普通要点直接写成完整平直的句子。

## 代码块、表格与行内代码

- **可运行命令与输出分离**：命令块中不带 `$` 或 `%` 提示符，只放可直接复制运行的指令；若需要展示输出，单独使用 `txt` 代码块放置，并用 `<UPPER_SNAKE>` 或 `$VAR` 表示占位符。
- **行内代码范围**：仅对文件路径、包名、命令、CLI 参数、配置键、环境变量、HTTP 方法与路径、代码标识符使用反引号；常规产品名称、文档分类和一般概念保持正文排版。
- **避免 JSX 花括号歧义**：在 `.mdx` 页面正文中，不要在代码块之外使用裸露的 `{变量}`，以免 MDX 解析器将其视为 JSX 表达式；需要示例路径参数时请写在行内代码内（如 `` `/v2/song/:id` ``）。
- **Fumadocs 链接**：同级与下级页面使用 `./文件名.md`，跨级页面使用 `/zh/...` 根相对路径，仓库源码使用完整 GitHub `blob/main` URL。详情见 [信息架构与文档类型](./content-types.md)。
